# 专注磁贴与主窗口计时同步修复

## 问题

主窗口在启动时读取一次桌面端任务数据，之后只推进本地显示时钟。专注磁贴调用暂停命令后，后端已停止计时，但主窗口仍持有旧的 timerStartedAt，返回主窗口后会继续显示计时中，并使耗时和专注统计继续增长。

## 修复

Rust 的暂停、开始/继续计时命令在成功保存数据并释放存储锁后广播 todo-data-changed 事件。主窗口订阅事件并刷新任务及专注历史，同时重新获得原生窗口焦点时也刷新，覆盖错过事件的情况。

读取期间再次发生变更时，丢弃该次读取并串行重读，避免旧响应恢复已暂停的计时状态。事件注册完成后额外刷新一次，覆盖首次读取与监听注册之间的空档；卸载时释放监听，包括异步延迟完成的注册。

此分支从 origin/main 创建，仅修复计时同步，不包含之前便签数据存储及 Markdown PR 的改动。

## 验证

新增 5 项桌面运行时回归测试，覆盖磁贴暂停后主窗口计时停止及历史更新、继续时排除暂停时长、窗口焦点兜底、读取与变更竞态、异步监听清理。修复前五项均失败，修复后全部通过。

全部 36 项前端测试、7 项 Rust 单元测试、前端构建、修改的 TypeScript 文件 ESLint 与 git diff --check 通过。运行时事件由测试模拟，未进行完整桌面 GUI 自动化回归。

手动复核：开始任务计时，打开专注磁贴，等待几秒后点击暂停，再返回主窗口；应显示暂停状态，等待后耗时不再增加。再次打开磁贴并继续，返回主窗口后应从已累计耗时继续计时，暂停期间不计入统计。

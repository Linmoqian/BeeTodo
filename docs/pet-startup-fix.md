# 桌宠启动恢复修复

## 问题

桌宠开关已持久化，但应用启动读取 petEnabled 后没有创建桌宠窗口。结果是设置显示已开启，重启后桌宠不出现，需要先关闭再开启才能恢复。

## 修复

主窗口通过 usePetWindow 统一根据 petEnabled 同步桌宠可见性。启动加载设置后自动恢复开启状态；侧栏和设置面板只修改设置，不再分别创建、关闭窗口；设置面板的桌宠开关受主窗口状态控制，避免两处控件显示不同状态。

窗口操作按顺序执行，过时的排队操作会被跳过。创建函数等待原生窗口创建完成后才返回，确保创建期间收到的关闭操作能找到并关闭窗口。创建失败会释放监听并传递错误，后续开关操作仍可继续。React StrictMode 的 effect 重放不会重复创建桌宠。

此分支独立基于 origin/main，不依赖便签或计时同步 PR。

## 验证

新增 12 项测试：设置已开启时自动恢复、关闭状态、异步设置加载、StrictMode、创建期间关闭、创建失败后恢复、浏览器预览、原生创建等待、原生创建错误清理、复用现有窗口，以及实际 AppShell/ThemeSettings 启动链路。

全部 43 项前端测试、前端构建、新增代码及 AppShell/窗口模块的 ESLint、git diff --check 通过。全仓库 lint 仍有此前已有的 22 项错误，未混入本次修复。原生窗口调用通过测试模拟，尚未执行完整桌面 GUI 回归。

手动复核：开启桌宠后从托盘退出应用并重新启动，桌宠应自动出现；关闭桌宠后退出并重启，桌宠应保持关闭。侧栏和设置面板开关均应正常，快速开关后最终可见性应与开关一致。
